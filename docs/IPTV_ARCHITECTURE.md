# Native IPTV contribution architecture

This branch prepares an IPTV contribution against NuvioDesktop `Dev` at
`897efe9`. Upstream submission remains conditional on explicit maintainer
approval of the feature request required by CONTRIBUTING.md.

## Scope and boundaries

- Desktop owns source management, network requests, encrypted storage, M3U and
  XMLTV parsing, Xtream live categories/streams, channel search/groups and guide.
- `features/livetv/LiveTvPlatform.kt` is the shared screen boundary. Navigation
  carries opaque channel IDs; credentials and stream URLs stay out of route keys.
- A desktop Live TV navigation entry opens a dedicated browse screen. Source
  management is reachable there. No mobile tab or native navigation ABI changes.
- Existing player surfaces gain explicit `isLive = false` and optional
  `onPreviousChannel` / `onNextChannel` callbacks. Live sessions do not read or
  write resume/watched progress, scrobble, fetch VOD metadata/skip intervals, or
  trigger next-episode logic. A LIVE indicator replaces the VOD timeline.
- The desktop Live TV player resolves channels from its profile repository and
  cycles only the channel IDs in the selected browse context. It preserves the
  existing native-player release handshake when switching or leaving.

## Data contract

`LiveTvModels.kt` defines source, channel, programme and state records. The
repository exposes `LiveTvRepository.forProfile(profileId)` with:

```kotlin
val uiState: StateFlow<LiveTvState>
suspend fun load()
suspend fun refresh()
suspend fun saveSource(source: LiveTvSource)
suspend fun removeSource(sourceId: String)
suspend fun setSourceEnabled(sourceId: String, enabled: Boolean)
```

Source IDs are generated by the source dialog. Channel IDs are stable and
source-qualified. Duplicate Xtream stream IDs keep the first category entry, so lazy
channel/guide rows always have unique keys. EPG entries are keyed by channel ID,
never by a globally ambiguous XMLTV ID. Network and parsing happen off the UI thread. Refreshes are
serialized, cancellation is preserved, and a failed refresh preserves usable
previous channel data. Disabling or deleting a source removes its channels.

M3U handling includes BOM/CRLF, quoted metadata, relative URLs, group names,
logos, EPG IDs, supported VLC request headers and header-specified EPG URLs.
Xtream uses the supplied host/base path and safely encodes credentials. Only
live categories/streams are included. XMLTV uses JVM streaming XML with DTD and
external entity resolution disabled, time-zone-aware timestamps, gzip support,
bounded decompression and current/upcoming programme selection.

## Persistence and privacy

The feature does not sync source configuration or send it to diagnostics.
Operating-system or manual backups can include the local app-data directory.
The entire source payload (including M3U URLs and file paths) is encrypted with
authenticated encryption. A randomly generated local key and ciphertext have
owner-only permissions (or the platform equivalent). This protects accidental
disclosure of the source file; it is not an OS credential-vault guarantee
against another process running as the same user. Storage failures surface
without destructive fallback. Network errors never display raw credentialed
URLs. No bundled playlists, credentials or subscription services are supplied.

## Lifecycle and verification

Navigation holds an in-memory launch ID, not URLs or the channel list. The desktop
wrapper keys playback by channel ID only after the old native controller confirms
release. Source edits apply to subsequent launches. A failed native release retains
the host and controller for the existing Back handshake; it disables playback Retry
and displays fixed restart/back guidance. Ordinary playback errors can still retry.
The runtime defaults to VOD and gates live UI actions as well as their callbacks.

Account reset bumps a process generation under the same monitor as repository
construction, writes and state publication. Old references become unusable, pending
IO cannot republish or save wiped sources, and replacement repositories wait until
old key/ciphertext deletion completes.

Validation covers M3U metadata/headers/duplicates, Xtream URL encoding and
responses, XMLTV offsets/XXE/gzip limits, encrypted profile isolation and source
lifecycle, and live/VOD playback policy. See `IPTV_CONTRIBUTION.md` for commands, the untouched upstream comparison,
actual Compose screenshots and remaining platform/provider smoke tests.
